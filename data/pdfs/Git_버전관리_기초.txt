Git 버전관리 기초

1. Git이란?
Git은 분산 버전 관리 시스템(DVCS)으로, 소스 코드의 변경 이력을 추적합니다.
리누스 토발즈가 2005년에 리눅스 커널 개발을 위해 만들었습니다.
중앙 서버 없이도 각 개발자의 로컬에 전체 히스토리가 저장됩니다.

2. 기본 워크플로우
git init: 새 저장소를 생성합니다. .git 폴더가 생성되어 버전 관리가 시작됩니다.
git add: 변경된 파일을 스테이징 영역에 추가합니다. git add . 으로 모든 변경을 추가합니다.
git commit: 스테이징된 변경을 저장소에 기록합니다. git commit -m "메시지" 형식으로 사용합니다.
git push: 로컬 커밋을 원격 저장소에 업로드합니다.
git pull: 원격 저장소의 변경을 로컬에 다운로드하고 병합합니다.

3. 브랜치 전략
git branch: 새 브랜치를 생성합니다. 브랜치는 독립적인 작업 공간입니다.
git checkout -b feature/login: feature 브랜치를 생성하고 전환합니다.
git merge: 다른 브랜치의 변경을 현재 브랜치에 병합합니다.
Git Flow 전략: main, develop, feature, release, hotfix 브랜치를 사용합니다.
GitHub Flow 전략: main과 feature 브랜치만 사용하는 단순한 전략입니다.

4. 충돌 해결
두 브랜치에서 같은 파일의 같은 부분을 수정하면 충돌(conflict)이 발생합니다.
<<<<<<< HEAD 와 >>>>>>> 사이의 코드를 직접 수정하여 해결합니다.
해결 후 git add → git commit 으로 병합을 완료합니다.
